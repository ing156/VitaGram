# Внутренний просмотр Mini Apps

Интеграция использует WebKitGTK 2.50.6 с экспериментальным
[портом Vita Stream Browser](https://github.com/ArchUserDesu/vita-stream-browser/tree/243a2e39965f8a3ad7d709b4d72b2fba7f01c1a9).
Архивы WebKit, WebCore, JavaScriptCore, Skia и зависимости собраны Vita-компилятором.
**С 0.38.54 основной VPK не содержит WebKit.** Движок и адаптер страницы
собираются в отдельный `webkit.suprx` с C-интерфейсом ABI 1. Создание и удаление
текстур выполняет основной клиент через callbacks своего vita2d/GXM-контекста.
STL-объекты и владение выделенной памятью через границу модуля не передаются.
Модуль имеет отдельный runtime newlib/pthread и heap 96 МиБ; heap основного
клиента остаётся 160 МиБ. Совместная работа runtime, TLS, загрузчика модулей и
фактический запас памяти **ещё не проверены на физической Vita**.

Открытие Mini App проверяет локальный подписанный архив в фоне; если его нет,
показывает размер совместимого дополнения из отдельного GitHub Release и кнопку
скачивания. Подтверждение передачи данных боту остаётся отдельным шагом после
установки. Обычные команды, текстовые и callback-кнопки не запускают загрузку.
Дополнение загружается один раз до выхода из клиента и не выгружается при
закрытии страницы; ошибка запуска требует перезапуска VitaGram.

Сборка и проверки на ПК не подтверждают загрузку `.suprx`, выполнение JavaScript
или Mini Apps на консоли. До публикации подписанного дополнения клиент показывает
ошибку получения выпуска; основной Telegram-клиент продолжает работать.
С 0.38.55 поток проверки/загрузки дополнения получает стек 256 КиБ, как поток
обновлений. Исправлено переполнение стандартного стека Vita 32 КиБ при входе
в проверку архива с локальным буфером 64 КиБ: оно происходило и при отсутствующем
движке, до проверки файлов. Отказ создания потока отображается как ошибка с повтором.

## Потоки и программная отрисовка Vita

В патче WTF используется реальная пара `sceKernelSuspendThreadForVM` /
`sceKernelResumeThreadForVM`, а `_sceKernelGetThreadContextForVM` получает
16 регистров CPU и 64 слова VFP для консервативного сканирования GC. Потоки
WTF и основные потоки Web/Network создаются с атрибутом VM `0x04000000`.
Обёртка `sceKernelCreateThread` добавляет этот атрибут только во время создания
потока WTF; обычные потоки TDLib сохраняют прежние атрибуты.

Регистрация выполняется в самом созданном потоке: `pthread_t` не подменяется
идентификатором ядра Vita. Вложенные остановки удерживают одну нативную остановку.
Ошибка получения регистров вызывает попытку возобновления; ошибка возобновления
сохраняет состояние удержания. Реестр не выделяет и не освобождает память под
своей блокировкой: остановленный поток может удерживать блокировку аллокатора.
JavaScriptCore аварийно прекращает работу при невозможности остановить поток,
вместо продолжения GC без его корней. В этом порте такая ошибка затронет весь
VitaGram, поскольку компоненты WebKit работают в одном процессе.

Декларации экспортов сверены с базой VitaSDK; формат контекста и атрибут VM —
с [описанием регистров Vita3K](https://github.com/Vita3K/Vita3K/blob/master/vita3k/kernel/include/kernel/types.h)
и [интерфейсом ForVM](https://github.com/Vita3K/Vita3K/blob/master/vita3k/modules/SceKernelThreadMgr/SceThreadmgr.cpp).
Реализация эмулятора не переносилась в VitaGram. Эти сведения и проверки на ПК
не подтверждают работу приватного ABI на физической консоли.

Для Vita отключено создание `LayerTreeHost`: страница рисуется в программный
backing store, который копируется в текстуру vita2d. Настройки страницы
принудительно отключают ускоренную композицию. Создание ImageBuffer для Canvas
на Vita сразу выбирает bitmap backend; SkiaPaintingEngine не создаёт GPU-пул
текстур и допускает только программные тайлы. Неожиданный запрос ускоренного
GraphicsLayer завершается assert, а не вызывает заглушки GLES.

## Сборка

Сначала подготовьте и соберите VitaGram по корневому README. Дополнительно нужны
Ruby, Bison, Flex и unifdef для генераторов WebKit, а также нативный C-компилятор
для локального ELF-конвертера.

```sh
sudo apt-get install ruby bison flex unifdef
bash scripts/build-webkit-vita.sh
cmake -S . -B build-modern \
  -DCMAKE_BUILD_TYPE=Release -DCMAKE_POLICY_VERSION_MINIMUM=3.5 \
  -DTD_ENABLE_TESTS=OFF \
  -DVITAGRAM_WEBKIT_ROOT="$PWD/external/webkit-vita"
cmake --build build-modern --parallel "$(nproc)"
```

Скрипт сохраняет исходники и объектные файлы в `external/webkit-vita-work`,
проверяет SHA-256 архивов и устанавливает библиотеки в `external/webkit-vita`.
SDK не изменяется. Локальный конвертер и его libelf/libyaml собираются в рабочем
каталоге; в staging-префиксе конвертер находится в `bin/vita-elf-create`.
CMake выбирает его только при включённом WebKit. WebKit использует OpenSSL
проекта и отдельную копию SQLite из TDLib с включёнными метаданными столбцов;
флаги SQLite основного клиента не меняются.
Скрипт проверяет хеш применённого интеграционного патча. При несовпадении
с кэшированными исходниками укажите новый `VITAGRAM_WEBKIT_WORK`; старые
исходники не пересобираются молча с пропущенными исправлениями.
Тонкие архивы WebKit преобразуются в самостоятельные архивы при установке.
Параметр `VITAGRAM_WEBKIT_WORK` позволяет выбрать другой рабочий каталог.

Результаты: лёгкий `build-modern/vitagram.vpk` и отдельный
`build-modern/vitagram-webkit-abi1-r1.zip`. Архив включает движок, маркер
совместимости и лицензии. При пустом `-DVITAGRAM_WEBKIT_ROOT=` собирается только
основной клиент; исходники, библиотеки и headers WebKit ему не нужны.
VitaSDK и обычные зависимости проекта по-прежнему требуются. MEM109 задан и в основном VPK заранее, поскольку режим
памяти нельзя включить дозагрузкой модуля.

Подписать дополнение существующим ключом релизов:

```sh
bash scripts/sign-webkit.sh build-modern/vitagram-webkit-abi1-r1.zip
```

Публикация выполняется отдельно: GitHub **pre-release** с тегом `webkit-abi1-r1`,
файлы `vitagram-webkit-abi1-r1.zip` и `vitagram-webkit-abi1-r1.zip.sig`.
Клиент запрашивает именно этот совместимый выпуск, а не latest. Дополнение
должно оставаться pre-release, чтобы не заменить latest обычного приложения.
Для аппаратной проверки без публикации скопируйте подписанные ZIP и `.sig` в
`ux0:data/vitagram/webkit/webkit-abi1-r1/` под именами `engine.zip` и `engine.sig`.
Клиент сам проверит и распакует их при открытии Mini App; вручную раскладывать
`.suprx` по каталогу `ready` не нужно.
Подпись ECDSA P-256/SHA-256 покрывает
`vitagram-webkit-v1\nwebkit-abi1-r1\n` и байты архива; подпись обычного VPK
не принимается как подпись дополнения. Изменение движка требует нового release ID;
изменение C-интерфейса — нового ABI. Нельзя заменять опубликованный r1 другими байтами.

Архив и подпись сохраняются в
`ux0:data/vitagram/webkit/webkit-abi1-r1/`. На первом открытии после запуска
архив повторно проверяется и распаковывается в staging; только затем проверяются
маркер совместимости, движок и лицензия и активируется каталог `ready`.
Ранее распакованный модуль без проверки архива не запускается. Обрыв загрузки,
отмена, неверная подпись и несовместимый архив не передаются загрузчику модулей.
Скачивание ограничено 96 МиБ, распаковка — 160 МиБ; проверка места резервирует
архив, максимальный распакованный объём и ещё 16 МиБ. Архив сохраняется для
повторной проверки без интернета; на карте одновременно хранятся архив и
распакованный модуль (примерно 77 МиБ для первого дополнения). Загрузка дополнения использует существующий
HTTPS-клиент обновлений и прямое соединение; настройки прокси страниц применяются
уже внутри запущенного WebKit.

## Адаптер запуска (без аппаратной проверки)

- Меню, inline-кнопка и ответная клавиатура вызывают методы TDLib
  `openWebApp` / `getWebAppUrl` после подтверждения передачи данных боту.
- Подписанный адрес открывается во встроенном WebKit. Внешний браузер
  не используется для подмены запуска Mini App.
- Сессия закрывается при выходе из чата, блокировке и `updateWebAppMessageSent`.
  Запоздалый ответ на отменённый запуск не открывает страницу.
- Страницы закрываются отдельно; один контекст и временное хранилище WebKit
  используются до выхода из VitaGram из-за singleton WebProcess в порте.
  Cookies живут в памяти до выхода из клиента. Проверка HTTPS-сертификата использует общий
  комплект CA VitaGram. Подписанные адреса, заголовки и cookies не трассируются.
- HTTPS-запросы WebKit идут через curl отдельно от TDLib.
  С 0.38.39 страницы Mini Apps используют включённый в настройках SOCKS5 или HTTP CONNECT
  (в интерфейсе — HTTPS), включая логин и пароль. SOCKS5 разрешает имена сайтов
  через прокси; для соединения с самим прокси используется DNS Vita. Сервер задаётся
  именем или IPv4-адресом. При выключенном прокси WebKit использует прямое соединение.
  MTProxy не передаёт веб-трафик: с 0.38.40 при его выборе Mini App пробует
  прямое соединение без предупреждения, а Telegram продолжает использовать MTProxy.
  Настройки применяются при каждом
  открытии; credentials не включаются в диагностические логи. Проверка на Vita нужна.
- Мост JavaScript ограничивает очередь команд, работает в основном фрейме
  и проверяет исходный HTTPS origin перед вызовом нативных действий.
  С 0.38.44 запрос счёта `web_app_open_invoice` показывает сообщение о недоступной
  оплате и возвращает `invoice_closed` со статусом `cancelled`: SDK освобождает
  ожидающий счёт и допускает повторное открытие. Платёжные методы TDLib не вызываются;
  идентификатор счёта проверяется и не записывается в журнал. Запрос вибрации
  принимается без действия, поскольку у Vita нет вибромотора.
- Тема передаётся из текущей палитры. Поддержаны основные события темы,
  размера окна, закрытия, кнопок Back/Main и `sendData` для ответной клавиатуры.
- Ввод: касание или крестовина с Cross; L/R прокручивают страницу;
  Square открывает текущую клавиатуру VitaGram для выбранного поля.
  С 0.38.43 свайпы прокручивают содержимое в обе стороны с затуханием инерции.
  Небольшое движение пальца остаётся касанием; после свайпа нажатие отменяется.
  Второй палец, смена пальца, клавиатура и контроллер прерывают жест.
  Сенсор скрывает курсор, а стик/кнопки возвращают его. Начало жеста за пределами
  страницы не захватывается при последующем перемещении на неё.
  Triangle переключает полноэкранный viewport 960×544 (544×960 при повороте),
  скрывая нативные панели. Повторный Triangle возвращает панели, Start закрывает
  Mini App; Select вызывает активную MainButton. Подсказка ввода удалена,
  ожидание загрузки показывается маленьким индикатором без текста поверх страницы.
  С 0.38.41 движение мыши, нажатия и колесо передаются через прямой API WebKit:
  PlayStationWebView не подключает обработчики ввода WPE backend. Для Vita колесо
  сохраняет величину в пикселях, нулевую горизонтальную составляющую и знак,
  а кнопка мыши — время события и состояние нажатия.
  С 0.38.42 Web-окно владеет касаниями поверх чата и папок; временная блокировка
  фоновых действий снимается в конце обработки ввода, чтобы отпускание пальца
  в следующем кадре распознавалось как нажатие. При закрытии окна блокировка
  сохраняется до нового касания, чтобы отпускание не активировало фон.
- Настройка гироскопа фотографий действует и на Web-страницу: используются тот же
  датчик и стабилизация 350 мс, без автоматического переворота на 180°.
  При ±90° обычный viewport меняется с 960×392 на 392×960, страница перестраивается,
  текстура поворачивается в прежней области окна, а координаты ввода преобразуются
  обратно в viewport. Нативные заголовок и кнопки VitaGram сохраняют положение.
  Касания приостанавливают автоповорот; открытая клавиатура откладывает его применение.
  Circle вызывает Back приложения, когда он доступен; Start закрывает просмотр.
  Ссылки проходят существующее подтверждение открытия.

Платежи, доступ к контактам/геопозиции, биометрия и прочие дополнительные
разрешения не реализованы. WebGL отключён; игры, которым он необходим,
не заработают в этой конфигурации.

Начиная с 0.38.25 внутренний просмотр разрешён при включённом шифровании.
`SharedMemoryVita` хранит кадры и крупные IPC-сообщения только в RAM: временные
файлы `shmem-*` больше не создаются. Дескриптор удерживает общий буфер до
освобождения последнего получателя; перед освобождением очищается весь буфер,
включая блоки больше 1 МиБ. Текстура vita2d очищается при закрытии страницы,
в том числе перед экраном блокировки. Общий лимит этих буферов — 32 МиБ;
при исчерпании выделение отклоняется, записи на карту вместо RAM нет.

Вложения IPC передаются одноразовыми идентификаторами внутри общего канала.
Закрытие любого конца или ошибка отправки освобождает неполученные вложения.
Крупное тело сообщения заполняется перед созданием передаваемого дескриптора.
Cookies используют SQLite `:memory:`, дисковый сетевой кэш отключён для
непостоянной сессии; резервное хранилище Vita также непостоянное.
Контекст и cookies в RAM сохраняются до выхода из VitaGram.
Новый клиент требует символ версии RAM-транспорта из WebKit: старый staging
с файловым транспортом не слинкуется. Аппаратные проверки ещё не выполнены.

С 0.38.34 URL-кнопки со ссылками `t.me/bot?startapp=...` и
`t.me/bot/app?startapp=...`, а также Mini App-ссылки `tg://…` разбираются
через `getInternalLinkType`. Для главного
приложения проверяются тип бота, ограничения и наличие Main App, для именованного
дополнительно запрашивается `searchWebApp`. После подтверждения вызываются
`getMainWebApp` / `getWebAppLinkUrl` с исходными стартовым параметром и режимом.
Право отправлять сообщения автоматически не выдаётся. Обычные ссылки на чаты
сохраняют прежний путь; запоздалые ответы отменённого запуска игнорируются.

## Диагностика запуска

С 0.38.36 левый стик плавно двигает курсор страницы с той же мёртвой зоной,
что и просмотр фотографий. Крестик нажимает в точке курсора, L/R прокручивают.
Скорость зависит от отклонения стика и времени кадра; задержка/возобновление
не вызывает большого скачка. При открытой клавиатуре курсор стиком не двигается.

С 0.38.37 `WKViewSetSize` передаёт геометрию DrawingArea, чтобы изменение
размера достигало Web-процесса. Проверка извлечённого production-метода
покрывает обычный resize, временное отсутствие DrawingArea и её позднее
появление. В аппаратном повторе 0.38.37 начальный кадр создан и передан окну,
но после фиксации документа отрисовка отмечена как замороженная; белая страница
пока не устранена.
`web_app_setup_swipe_behavior` и `iframe_ready` принимаются без нативного
действия: у этого окна нет жеста закрытия свайпом и родительского iframe.
Запросы доступа к телефону, сообщениям, платежам и другим данным это не разрешает.

С 0.38.35 идентификатор логического процесса хранится отдельно для каждого
главного RunLoop; рабочие потоки наследуют тип своего компонента. Закрытие
IPC останавливает RunLoop, не вызывая `exit`/`_exit` и watchdog завершения всего
приложения. UI ожидает завершения потока не более 1 мс и никогда не удаляет
ещё работающий поток. Не завершившийся за это время объект потока сохраняется
до выхода из приложения. Singleton-компоненты нельзя инициализировать повторно:
после их остановки требуется перезапуск VitaGram. Обычное закрытие страницы
продолжает использовать живой контекст. Проверки разрешений cookies не отключены.
Отказ запуска передаётся окну через штатный callback WebKit, чтобы оно
получало ошибку вместо ожидания несуществующего компонента.

Начиная с 0.38.33 включите **Start → Журналы диагностики → Производительность**
перед воспроизведением проблемы, затем перезапустите VitaGram. Дополнительно
к performance.log появится `ux0:data/vitagram/webapp.log`. Первая метка
`client_ready code=0` подтверждает запуск лёгкой основы без загруженного движка.
Фактическую инициализацию дополнения подтверждает `engine_initialized code=1`. Записываются только фиксированные названия этапов
и числовые коды: URL, имя бота, идентификаторы аккаунта, текст кнопок, cookies
и сообщения JavaScript в этот журнал не попадают. По умолчанию запись выключена.

Если подтверждение открытия не появилось, важны `touch_release`, `toolbar_tap`,
`menu_open`, `inline_tap`, `button`, `rejected` и `confirm_drawn`.
`touch_release` содержит маску: 1 — касание заблокировано, 2 — распознано как
перетаскивание, 4 — занято другим элементом управления. `toolbar_tap` с кодом 0
означает, что условия открытия панели бота не выполнены. `rejected`: 1 — нет
готового чата, 2 — неверный индекс кнопки, 3 — бот не определён или ограничен,
4 — неподдерживаемый тип кнопки. `link`/`callback` означают другой тип действия,
а не прямую кнопку Mini App.

После подтверждения `link_resolve` отмечает разбор URL-кнопки, `link_main`/`link_named` — распознанный
тип Mini App, `link_bot_ready` — проверенного бота. `link_other code=1` означает
обычную ссылку запуска бота (`start`), которая не является ссылкой Mini App.
`request`/`ready` отмечают обмен с TDLib; затем идут
`engine_open`, инициализация, создание контекста/окна, `load_request`,
`load_queued`, события навигации и первая пара `paint_begin`/`paint_done`.
Каждая запись закрывает файл, сохраняя последний достигнутый этап при зависании.
После проверки выключите журнал. Аппаратная проверка этих этапов ещё требуется.

`ipc_invalid_message code=N` — номер сообщения WebKit, отклонённого сетевым
компонентом. По нему можно найти тип сообщения в исходниках той же сборки;
содержимое сообщения и адрес страницы не записываются.

С 0.38.36 `navigation_commit` означает фиксацию загруженного документа.
`paint_done` сам по себе не подтверждает загрузку страницы: начальная пустая
поверхность может быть нарисована до `navigation_start`.
Метка `bridge_unsupported_web_app_…` содержит только название известного
действия из фиксированного списка SDK; неизвестные строки записываются как
`bridge_unsupported_unknown`, без исходного значения и параметров.

`engine_trace code=N` отмечает первое достижение сетевого этапа за открытие.
Повторы одного этапа не записываются; произвольные сообщения WebKit, числовые
дампы содержимого и текст ответов остаются выключенными.

## Проверка

`bash tests/run-webkit-process-tests.sh` компилирует настоящий
`ProcessIdentifier.cpp` с небольшими заглушками типов и проверяет отдельные
идентификаторы UI/Web/Network, рабочие потоки и конкурентную генерацию ID.
Из реальных исходников извлекаются обработчик закрытия и блоки выбора
callback: проверяется остановка RunLoop без exit/watchdog на Vita и сохранение
поведения GTK/WPE/остальных платформ, а также отложенное уведомление об отказе
запуска. Адаптер процессов компилируется целиком
с имитацией Vita API: проверяются отказ запуска, повтор, запрет повторного
старта singleton, ограниченное ожидание и отсутствие удаления живого потока.

На ПК: `bash tests/run-webkit-threading-tests.sh` проверяет production-код
реестра с имитацией нативных экспортов: регистры, вложенность, ошибки и атрибуты
потоков. Vita-компилятор проверяет этот же код с настоящими заголовками SDK.
Также выполняются `bash tests/run-bot-buttons-tests.sh`, `bash tests/run-transfer-tests.sh`
и `bash tests/run-i18n-tests.sh`. Они проверяют протокол запуска, устаревшие ответы,
ограничения `sendData`, origin, очередь моста, палитры и нативные кнопки.
`bash tests/run-webkit-memory-tests.sh` компилирует настоящий `SharedMemoryVita.cpp`
и обёртку дескрипторов с небольшими заглушками типов WebCore/WTF: проверяются
бюджет RAM, полная очистка, границы отображения, общие буферы, крупные сообщения,
повторные/неверные идентификаторы, закрытие канала и обычные файловые дескрипторы.
Для этого теста нужны подготовленные исходники WebKit.
Эти проверки не запускают браузер и не авторизуют Telegram Mini App.
Отдельно проверена совместимость с официальным
[JavaScript SDK Telegram](https://telegram.org/js/telegram-web-app.js):

```sh
node tests/webapp_sdk_test.js /путь/к/telegram-web-app.js
```

Проверка SDK выполняется в среде Node с имитацией DOM: инициализация, тема и CSS,
размер окна, безопасные области, события MainButton/BackButton и точные данные
`sendData`. Она не заменяет проверку реального движка.

Конвертер прошёл upstream-тесты VitaSDK. Дополнительно выполнено:

```sh
python3 tests/check_webkit_pic.py build-modern/src/webview/module/vitagram-webkit build-modern/src/webview/module/vitagram-webkit.velf
```

Проверено 15 738 исходных BASE_PREL и 29 456 ссылок GOT_BREL:
27 455 уникальных релокаций в Sony ELF, точные сегменты/смещения и адреса
назначения, отсутствие повторного переноса GOT. Это проверка формата и
соответствия адресов; она не исполняет код загрузчика на Vita.

Выбранные публичные примеры для проверки на Vita:

| Бот | Что проверить | Выполнено на Vita |
| --- | --- | --- |
| [@WantToPayBot](https://t.me/WantToPayBot) | Кнопка меню, загрузка Mini App, возврат в чат | Нет |
| [Durger King](https://t.me/durgerkingbot) | Меню, загрузка магазина, корзина, MainButton, возврат | Нет |
| [@tma.js bot](https://t.me/tmajsbot) | События Telegram API, тема, поля ввода, неподдерживаемые функции | Нет |
| [GAMEE](https://t.me/gamee) | Загрузка тяжёлого интерфейса, ограничения памяти и WebGL | Нет |

Отдельно на устройстве нужны замеры свободной памяти рядом с TDLib,
повторные открытия/закрытия, возврат из сна, блокировка хранилища и проверка
отсутствия временных файлов при загрузке страниц. Процессы WebKit в этом порте
работают как потоки одного приложения: отдельной изоляции памяти от TDLib нет. Стабильность и пригодность порта для обычной
сборки пока не подтверждены аппаратными проверками.
