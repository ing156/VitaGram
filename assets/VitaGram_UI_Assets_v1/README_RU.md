# VitaGram UI Assets v1.2

Готовый набор PNG-текстур для оформления **существующего** UI VitaGram в vita2d.
Это визуальный ресурсный пакет, а не переписывание текущей логики и не готовое приложение.

## Состав

- `themes/dark/9slice/` и `themes/light/9slice/` — панели, строки, вкладки, меню, фокус, скроллбар, прогресс, бейджи и т. д. с RGBA-прозрачностью.
- `themes/*/fixed/` — волнообразные фоны 960×544 (основной и альтернативный), градиентная шапка 960×40 и нижняя панель 960×44, индикаторы.
- `themes/*/icons/` — отдельные контурные иконки 32×32.
- `themes/*/buttons/` — отдельные кнопки ×, ○, □, △, L, R, START, SELECT, крестовина; 48×48.
- `themes/*/ui_icons_atlas.png` — объединение иконок.
- `themes/*/ps_buttons_atlas.png` — объединение обозначений кнопок.
- `manifest.json` — имена, размеры, отступы 9-slice и координаты спрайтов в атласах.
- `previews/` — демонстрационные экраны 960×544, НЕ реальные скриншоты VitaGram.
- `example_vita2d.cpp` — минимальная вспомогательная функция 9-slice.

## Использование с vita2d

1. Скопируйте нужные PNG в `app0:...` и загрузите их с `vita2d_load_PNG_file()` при инициализации экрана/темы.
2. Вызовите `draw_9slice()` с параметрами из `manifest.json`. Это девять текстурных блитов — **не рисование геометрии**.
3. Иконки рендерьте через `vita2d_draw_texture_part()` из общего атласа либо загружайте индивидуальные PNG.
4. Для переключения темы загрузите соответствующий набор ресурсов и корректно выгрузите старые текстуры после завершения их использования.
5. Текст, аватары, превью, пользовательские вкладки, данные меню и видеокадры оставьте динамическими в текущем коде.

## Важные ограничения

- Все файлы RGBA PNG; текстуры с прозрачностью.
- `9-slice` не означает единственный draw call: один элемент обычно требует 9 фрагментов текстуры.
- Не сжимайте угол 9-slice: итоговый размер элемента >= сумме соответствующих отступов.
- Никаких фотографий, пользовательских текстов или количества вкладок в PNG не зашито.
- Атлас иконок имеет прозрачный фон, координаты берите из манифеста.
- Ресурсы полностью созданы для этого пакета; готовые системные файлы/шрифты PS Vita не включены.
- Надписи и текст в previews — демонстрационные; шрифты из окружения сборки НЕ включаются в пакет.
- Сборка и запуск на реальной PS Vita не выполнялись. Совместимость с используемым форком vita2d надо проверить.

## Рекомендации по оптимизации

- Загружайте текстуры один раз.
- Используйте `ui_icons_atlas.png` и `ps_buttons_atlas.png` вместо большого числа маленьких отдельных загрузок.
- Избегайте загрузки обеих тем одновременно при дефиците памяти.
- Фиксированные фоны и шапки можно рисовать одним блитом.
- Не создавайте новые текстуры на каждом кадре.
- Старайтесь сгруппировать отрисовку 9-slice панелей по текстуре/экрану.

## Обновление v1.1 — волнообразные обои PlayStation Vita

Обновлены оба штатных `background_960x544.png`. Вместо почти одноцветной заливки используются оригинальные плавные волны в духе интерфейса PS Vita: многослойные полупрозрачные ленты, мягкие градиенты, светлые блики. Светлая и тёмная темы согласованы между собой.

Дополнительно доступны более контрастные варианты:

- `themes/dark/fixed/background_alt_960x544.png`
- `themes/light/fixed/background_alt_960x544.png`

Обычный фон остаётся по прежнему пути `fixed/background_960x544.png`, поэтому код загрузки менять не требуется. Обе версии — готовые **статические** RGBA PNG 960×544; отрисовка — один `vita2d_draw_texture(texture, 0, 0)` на кадр. Никакой runtime-генерации волн и шейдеров не нужно.

Фоны не содержат текста или изображений пользователя. Их следует рисовать под остальными элементами UI; при открытых чатах наиболее яркие участки не должны затруднять чтение.

Для повторной генерации волновых фонов в пакете есть `generate_wave_backgrounds.py` (только offline, зависимости Python/Pillow/CairoSVG), он не нужен в VPK.

## Шаблон и композиции из JSON

### Динамические маски в приложении (0.37.84)

С версии 0.37.94 добавлены независимые роли `icon` (обычные и угловые значки),
`notification` (непрочитанные точки, их ореол и счётчики тем),
`control_active`/`control_inactive` (RadioButton в опросах), `delivery`
(отметки отправки/прочтения). Они доступны в общем списке Palette Studio;
состояния RadioButton показаны на экране предпросмотра «Опрос».
Экспорт нового редактора требует VitaGram 0.37.94+. Прежние JSON принимаются:
отсутствующие роли наследуют `text`, `accent`, `muted`, `green`, а цвет
непрочитанного по умолчанию остаётся `#1E90FF`.

С версии 0.37.89 пользовательские JSON загружаются отдельными темами из
`ux0:data/vitagram/palletes/` (именно такое написание). Каталог сканируется
при запуске; после копирования/изменения файлов перезапустите приложение.
В выпадающем списке показано имя файла без `.json` и пятицветный образец.
Длинные подписи обрезаются по ширине строки; настройки хранят полное имя,
поэтому добавление/сортировка других файлов не меняет выбранную тему.
Имя без расширения ограничено 96 байтами UTF-8, файл — 8 КиБ;
загружаются первые 64 корректных файла в порядке имён. Повторяющиеся ключи,
неизвестные роли, некорректные цвета, каталоги и ссылки пропускаются.
Обязательны `background`, `surface`, `text`, `muted`, `accent`; остальные роли
берутся из стандартной темы подходящей яркости. Удалённая/некорректная
выбранная тема заменяется Тёмной при следующем запуске. Старый одиночный
`ux0:data/vitagram/palette.json` продолжает работать для стандартных тем;
пользовательские темы из `palletes` он не переопределяет.

[Palette Studio для Windows/Linux](../../tools/palette-editor/README.md)
создаёт эти JSON без PNG. Это автономный HTML с настоящими масками,
каталогами цветов, предпросмотром и экспортом. Сборка:
`python3 scripts/build-palette-editor.py`; результат:
`build-modern/palette-editor/VitaGram Palette Editor.html`.

С версии 0.37.85 готовые палитры доступны в **Start → Настройки → Тема**:
Светлая, Тёмная, VHBB, Little Greene / Светлая, Little Greene / Тёмная,
black-blue / Тёмная, black-red / Тёмная — всего семь тем.
Сохранённые ID оставшихся тем не изменены; удалённые варианты открывают Тёмную.
Выбор сохраняется после перезапуска и используется до разблокировки хранилища.
Во время переключения показывается заставка «Идёт смена темы…» до завершения
загрузки и перекраски. Все четыре JSON-палитры входят в VPK; переносить файлы вручную
для этих вариантов не нужно. Названия режимов и заставка локализованы.

С версии 0.37.86 строка «Тема» открывает выпадающий список. У каждой темы есть
образец из пяти цветов: фон, поверхность, акцент, текст и выделение. Стрелки
и левый стик перемещают фокус без перекраски. × или касание строки применяет
выбор; ○, Start и касание вне списка закрывают его без изменений. Повторное
подтверждение текущей темы не записывает настройки и не запускает перекраску.

При переключении между Светлой, Тёмной и именованными палитрами приложение
использует уже загруженные маски, текстуры и координаты атласов. Палитры и
образцы цветов кэшируются при первой загрузке. PNG не читаются повторно,
GPU-текстуры не пересоздаются; перекрашиваются только текстуры с изменёнными
ролями. Для непрозрачных участков смешивание выполняется без деления на
переменный знаменатель, с тем же побайтовым результатом. Переходы к VHBB
и обратно по-прежнему загружают её отдельную геометрию и ресурсы.

Контрольный замер на ПК с AddressSanitizer/UBSan: полная загрузка 72,7 мс,
среднее переключение пяти кэшированных палитр 16,5 мс; повторных чтений PNG
и выделений GPU-текстур нет. Смешивание 100×64×64×5 слоёв: 40,9 → 18,2 мс.
Это сравнение путей на ПК, а не замер FPS или времени на физической Vita.

Список показывает до восьми строк; пользовательские темы добавляются после
встроенных. Длинный список прокручивается кнопками, стиком и свайпом.
Незаполненные строки не рисуются и не реагируют на касание.

С версии 0.37.88 угловые кнопки меню и вложений используют цвет текста поверх
поверхности темы, поэтому видны и в светлых палитрах. Обычное заполнение батареи
использует `header_text`, а низкий заряд, четверть заряда и зарядка — отдельные
роли `battery_low`, `battery_warning`, `battery_charging`. Приложение вычисляет
их из `danger`, `warning`, `green`, осветляя или затемняя до контраста 3:1
с обоими краями градиента шапки. При необходимости так же корректируется
`header_text`. Для всех предустановок контраст проверяется на ПК; цвета
пересчитываются и при изменении JSON во время работы.

`masks/` содержит единый набор **белых масок с полутоновой альфой** для 81 элемента.
Прозрачные участки не рисуются; альфа сохраняет сглаживание, тени и градиенты.
Заливка, обводка, фокус, тень, блики и цветовые области значков разделены
по ролям. В `masks/manifest.json` указаны роли, позиции и размеры каждого слоя.
Панели сохраняют отступы 9-slice, атласы — координаты исходных спрайтов.
Цвета не зашиты в маски. Волны используют прежнюю SVG-геометрию; цвет каждой
ленты задаётся ролью, а переходы сохраняются в её альфе.

Светлая и тёмная темы используют эти маски. При изменении палитры приложение
пересобирает пиксели уже загруженных текстур **между кадрами**, затем рисует их
обычным способом. PNG повторно не загружаются, новые GPU-текстуры не создаются,
число вызовов рисования не увеличивается. Покрытие масок хранится в RAM в виде
однобайтной альфы, с обрезкой пустых краёв и общим пределом 16 МиБ.
VHBB сохраняет своё исходное оформление и не использует эти маски.

Готовые файлы цветов: `palettes/little-greene-light.json`,
`palettes/little-greene-dark.json`, `palettes/black-blue/palette.json`,
`palettes/black-red/palette.json`.
Для применения скопируйте один из них на Vita как:

```text
ux0:data/vitagram/palette.json
```

При выбранной стандартной Светлой или Тёмной теме файл подхватывается без перезапуска,
не чаще раза в секунду. Удаление файла возвращает палитру выбранной темы.
Некорректные HEX, неизвестные роли, повторяющиеся ключи и повреждённый JSON
сохраняют последнюю рабочую палитру. Файл ограничен 8 КиБ. Он содержит только
цвета и хранится открыто, независимо от шифрования данных аккаунта.
Допускается частичная палитра: отсутствующие роли берутся из выбранной темы.
Именованные предустановки используют свою палитру из VPK; внешний файл
`palette.json` их не переопределяет.
Светлый/тёмный режим рисования определяется по яркости фона и текста.

Из кода можно передать значения напрямую, между кадрами:

```cpp
ui_skin::set_palette(R"({"surface":"#EDEAE0","accent":"#0058A3"})");
```

Для новой композиции из каталога **достаточно создать JSON цветов**, без PNG:

```bash
python assets/VitaGram_UI_Assets_v1/generate_theme.py --palette-only \
  assets/VitaGram_UI_Assets_v1/compositions/little-greene-dark.json \
  build-modern/palettes/little-greene-dark
```

Скопируйте полученный `palette.json` по указанному пути на Vita.
Этот режим требует только стандартную библиотеку Python. Каталог
`assets/little-greene.json` сохранён по просьбе пользователя.
Темы Little Greene — использованы материалы @ElvisSuperStar007.
Доступен также Open Color (MIT) и локальный импорт JSON в мастере;
см. [источники и права](../../tools/palette-editor/CATALOG-SOURCES.md).

Маски нужно пересоздавать только при изменении **форм** assets:

```bash
python assets/VitaGram_UI_Assets_v1/generate_masks.py /путь/к/новому/каталогу/masks
```

После проверки замените каталог `assets/VitaGram_UI_Assets_v1/masks/`.
Набор входит в VPK автоматически. Для генерации масок нужны Pillow и CairoSVG;
при обычной сборке они не требуются. Контраст следует проверять для полной
композиции; произвольные частичные runtime-изменения приложение проверяет по
формату, без автоматического подбора цветов.

Проверки: `bash tests/run-ui-mask-tests.sh` (C++, системные libpng/Jansson)
и `python tests/theme_composition_test.py` (Pillow/CairoSVG).
Проверяются настоящие PNG, перекраска без чтения файлов и выделения текстур,
альфа, одинаковые по размеру правки файла палитры, смена темы, ошибки JSON
и освобождение ресурсов. Скорость смены палитры на физической Vita не измерена.

### Статические экспорты для просмотра на ПК

`build_assets_source.py` — переиспользуемый шаблон форм панелей, скруглений,
теней, волн и атласов. `generate_theme.py` подставляет в него цвета композиции
из указанного в композиции JSON-каталога.
Текущие PNG приложения при этом не меняются. Формы имеющихся иконок берутся
из `themes/light/icons/` или `themes/dark/icons/`; сигнальные цвета батареи,
красного значка выхода и обозначений кнопок Vita сохраняются.

Примеры композиций: `compositions/little-greene-light.json`,
`compositions/little-greene-dark.json`.
Для этих примеров используется `assets/little-greene.json`.

Композиция назначает пять ролей по **точному полю `code`** каталога:

```json
{
  "name": "Little Greene · Slaked Lime",
  "mode": "light",
  "catalog": "../../little-greene.json",
  "colors": {
    "background": "Slaked Lime Mid",
    "surface": "Slaked Lime",
    "text": "Basalt",
    "muted": "Obsidian",
    "accent": "Hicks' Blue"
  }
}
```

Путь `catalog` отсчитывается от файла композиции. `mode` — `light` или `dark`.
Заголовок, выделение, границы, тени, прогресс и оттенки волн выводятся из этих
пяти цветов. Промежуточные оттенки смешиваются и могут отсутствовать в каталоге.
Выбор сочетания задаётся композицией; каталог сам по себе не содержит готовых
гармоний. Повторяющиеся названия допустимы, повторяющиеся коды — ошибка.

Зависимости те же, что у исходного генератора: Python, Pillow, CairoSVG,
системная Cairo и DejaVu Sans для демонстрационного текста. Установите Python
зависимости в отдельное окружение (например, `python -m pip install Pillow CairoSVG`).
Из корня проекта:

```bash
python assets/VitaGram_UI_Assets_v1/generate_theme.py \
  assets/VitaGram_UI_Assets_v1/compositions/little-greene-light.json \
  build-modern/theme-previews/little-greene-light
```

Нужен новый выходной каталог. На выходе:

- `themes/<mode>/` — панели, фоны, иконки и атласы PNG RGBA8;
- `manifest.json` — размеры, отступы, координаты спрайтов и полная палитра;
- `palette.json` — все разрешённые цвета ролей;
- `composition.json` и `catalog.json` — переносимый рецепт для повторной генерации;
- `previews/<mode>_list_960x544.png`, `previews/<mode>_chat_960x544.png`,
  `previews/comparison.png`, `previews/catalog.png` — демонстрации реальных текстур.

Перед генерацией проверяются HEX, коды, контраст основного и вторичного текста
на фоне и основных подложках (не ниже 4,5:1), текста шапки (4,5:1), акцента
на панели (3:1). Эти расчёты относятся к непрозрачным заливкам. Сигнальные
значки, обои и прозрачность карточек требуют визуальной проверки.
При ошибке готовый пакет не публикуется; существующий выходной каталог
не перезаписывается.

Этот статический экспорт предназначен для просмотра на ПК и не заменяет весь
штатный набор `ui/` целиком. Для динамической перекраски используйте только
`palette.json` и общий набор масок, как описано выше. Отдельного пункта выбора
каталога красок в настройках нет; готовые композиции выбираются строкой «Тема».
VHBB не используется как шаблон.

Проверка: `python tests/theme_composition_test.py` из корня проекта в окружении
с теми же зависимостями. Тесты создают свой мини-каталог, проверяют ошибочные
входные данные и генерируют оба режима; локальные каталоги красок им не нужны.

## Значки действий чата
`trash` — корзина для удаления сообщений и чата; `leave` — красная дверь со стрелкой для выхода из группы/канала. Обе темы: 32×32 RGBA, шестая строка атласа. Старые координаты сохранены. Обновление только этих значков: `python add_menu_icons.py` (Pillow).
`reply` и `forward` — контурные изогнутые стрелки ответа и пересылки, также 32×32. Координаты `forward` сохранены, `reply` добавлен в шестую строку.
`clear-history` — контурная метла для очистки истории, 32×32 в обеих темах. «Удалить чат» и «Покинуть группу» используют красный `leave`; удаление сообщения — `trash`.

## Тема VHBB

`themes/vhbb/` — отдельная тема в формате этого пакета: сине-фиолетовые панели,
глянцевая голубая подсветка и общие с остальными темами плавные волны без логотипа VHBB.
Своя палитра обоев: основа `#12246B`, фиолетовый `#50448D`, синий `#117BDD`,
блики `#95D6FF`. Есть обычный и более контрастный варианты 960×544. Выбор: Start → Настройки →
Тема → VHBB. Существующие шрифты и значки VitaGram сохранены.

Поверхности и шапка адаптированы из Vita Homebrew Browser; исходные PNG находятся
в `themes/vhbb/source/`. Авторство и лицензия CC BY-NC-SA 4.0 указаны в
`themes/vhbb/NOTICE.txt` и `LICENSE.txt`; оба файла входят в VPK.
Генерация: `external/font-tools-venv/bin/python assets/VitaGram_UI_Assets_v1/generate_vhbb_theme.py`
из корня проекта (Pillow/CairoSVG). Скрипт обновляет только новую тему и её записи в manifest,
копируя текущие атласы значков из тёмной темы. После изменения значков запускайте
его снова. Превью реальных текстур: `themes/vhbb/preview_960x544.png`.
